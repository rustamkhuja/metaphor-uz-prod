# 07. Безопасность и конфиденциальность

## Вывод

[РЕКОМЕНДАЦИЯ] Публичный запуск допускается только после заполнения владельца, контактов, фактического LLM-провайдера, географии обработки, сроков хранения, порядка удаления и юридической проверки. HTML-страницы в пакете являются техническим проектом, а не юридическим заключением.

## Контроли, реализованные в коде

- `store=false` в Responses API;
- содержание raw input не хранится по умолчанию;
- generated output не хранится по умолчанию;
- сохраняются технические метрики, необходимые для лимитов, стоимости и воронки;
- опциональное редактирование телефонов, email, карт и URL;
- опциональное Fernet-шифрование при специально разрешённом хранении raw input;
- подписанная HttpOnly anonymous session;
- лимит длины и бесплатный лимит;
- safety-блокировка прямых угроз и self-harm;
- premium fail-closed;
- административный API key;
- Telegram webhook secret;
- единый дневной AI-бюджет для продукта и агентов;
- HTTPS и security headers через Caddy;
- публикация только из approved state;
- API-ключи отсутствуют во frontend;
- ежедневная автоматическая очистка данных по retention;
- ежедневный PostgreSQL backup с retention 14 дней;
- production startup прекращается при mock provider, SQLite, HTTP, стандартных секретах, draft-версиях policy/terms, `LEGAL_LAUNCH_APPROVED=false` или placeholders в legal pages.

## Обязательная production-приёмка

1. установить уникальные секреты через `scripts/generate_secrets.py`;
2. закрыть `/operator` identity proxy/VPN и не полагаться только на API key;
3. проверить создание backup и выполнить пробное восстановление;
4. проверить фактическое выполнение retention job;
5. определить применимость регистрации базы персональных данных;
6. оформить фактические договоры и уведомления об обработке;
7. выполнить SAST, dependency scan и проверку контейнеров;
8. провести prompt-injection, abuse и rate-limit тесты;
9. подтвердить отсутствие полного пользовательского текста в application/reverse-proxy logs;
10. утвердить incident response и контакты владельца;
11. проверить условия и фактический retention внешнего AI-провайдера;
12. выполнить внешний pentest публичных API до масштабного продвижения.

## Классификация инцидентов

| Уровень | Пример | Реакция |
|---|---|---|
| P0 | утечка ключа/данных, массовая опасная генерация | остановить API и публикацию, сменить секреты, сохранить evidence, уведомить ответственных |
| P1 | ошибочные платежи, публикация неутверждённого материала | отключить контур, провести расследование и rollback |
| P2 | деградация качества одного языка | переключить модель/промпт, включить ручную проверку |
| P3 | единичный UX-дефект | backlog с датой исправления |
